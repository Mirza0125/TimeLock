# Requirements: ScreenLimiter

**Defined:** 2026-09-25
**Core Value:** Set a limit on an app and it is reliably blocked when time runs out — on any Android phone, even offline — and removing the limit restores the app instantly.
**Source of detail:** `docs/PRODUCT_SPEC.md` (section refs in brackets), corrected by `.planning/research/SUMMARY.md`.

## v1 Requirements

Requirements for the Android v1.0 release. Each maps to exactly one roadmap phase.

### Foundation & Validation

- [x] **FND-01**: Developer can build and run the Expo SDK 57 app (prebuild, New Architecture, TypeScript ~5.9) on the emulator AVD `Medium_Phone_API_36.1` from a clean checkout with documented commands
- [ ] **FND-02**: All native Android config (manifest entries, accessibility service XML, `<queries>`, permissions) is generated by Expo config plugins; `android/` is never hand-edited and a clean `prebuild --clean` reproduces the same app
- [ ] **FND-03**: A block-launch spike on API 36 determines whether a bound AccessibilityService can start the block Activity from background; the result is recorded and the `GLOBAL_ACTION_HOME` + notification fallback is implemented and exercised either way [§13.5]
- [ ] **FND-04**: Lint (ESLint incl. no left/right style rule), Prettier, `tsc --noEmit`, Jest, ktlint and JUnit run with a single command each and pass on the empty scaffold
- [x] **FND-05**: The `ScreenGuard` TypeScript contract (`AppRef`, `Capabilities`, `PermissionState`, rule types) and shared JSON rule-evaluation test vectors exist before either evaluator is written [§12.2, §16.1]

### Enforcement Core (Android native)

- [ ] **ENF-01**: User can see all launchable apps with name, icon and category, excluding this app, launcher, dialer, emergency apps and Settings, without `QUERY_ALL_PACKAGES` [§6.1]
- [ ] **ENF-02**: App list updates within 5 s when an app is installed or uninstalled [§6.1]
- [ ] **ENF-03**: App records per-app foreground minutes and opens per day from usage events, within ±2 min of Digital Wellbeing over a 4 h usage day [§6.2]
- [ ] **ENF-04**: Screen-off time is not counted; split-screen and PiP apps are counted [§6.2]
- [ ] **ENF-05**: Kotlin LimitEngine and TS reference evaluator produce identical results for every shared test vector [§6.3, §20]
- [ ] **ENF-06**: Enforcement (detection, evaluation, blocking) works with the React Native process killed, offline, and after device reboot [§13.4]
- [ ] **ENF-07**: Rules, grants and usage history persist in native Room storage; usage history kept 90 days [§16.2]
- [ ] **ENF-08**: Changing the device clock or timezone recomputes day boundaries and re-evaluates rules immediately; session timers use monotonic time [§13.4]
- [ ] **ENF-09**: A watchdog detects the accessibility service being disabled/killed within 15 min and notifies the user with a fix link [§6.12]

### Limits

- [ ] **LIM-01**: User can set a daily time limit (5 min–23 h 55 min) on one or more apps, optionally per weekday [§6.3]
- [ ] **LIM-02**: User can set a shared daily limit on a category or custom group of apps [§6.3]
- [ ] **LIM-03**: User can create a schedule/downtime (windows may cross midnight, per weekday) that blocks all or selected apps with an allowlist [§6.3]
- [ ] **LIM-04**: User can set a session limit (session length + break length) on apps [§6.3]
- [ ] **LIM-05**: User can set a maximum number of opens per day on apps [§6.3]
- [ ] **LIM-06**: User can enable/disable any limit with a toggle and edit or delete it at any time, with no lock or cooldown
- [ ] **LIM-07**: Adding, editing, toggling or removing a limit takes effect immediately; if the current app is no longer blocked, the block screen closes within 1 s [§6.3]
- [ ] **LIM-08**: When several limits apply, the most restrictive wins per the documented evaluation order; the global allowlist is never blocked [§6.3]
- [ ] **LIM-09**: User can start a focus session (25/50/90 min or custom, presets Study/Work/Sleep) where only allowlisted apps are usable, and end it early [§6.6]

### Block Experience

- [ ] **BLK-01**: When a limit is reached, the app is covered by a full-screen block screen within 1.5 s (or sent home via fallback) [§6.4]
- [ ] **BLK-02**: Block screen shows the app, the reason (daily / downtime / session / opens) and when it becomes available, in the selected language [§6.4]
- [ ] **BLK-03**: User can close the app or do a 30 s breathing exercise from the block screen [§6.4]
- [ ] **BLK-04**: User can get extra time (default 5 min, max 3/app/day, configurable) after a friction step: breathing, typed phrase, or wait timer [§6.5]
- [ ] **BLK-05**: Returning to a blocked app via back, recents, notification or split-screen shows the block again [§6.4]

### Onboarding & Permissions

- [ ] **ONB-01**: First launch lets the user pick language, see a 3-slide welcome, choose mode (Self / Parent / Child) and theme [§5.1]
- [ ] **ONB-02**: Before opening accessibility settings, the user sees a prominent disclosure (what is accessed, why, what is never accessed) and must tap an explicit consent button [§5.2, §22]
- [ ] **ONB-03**: User is guided to grant Usage Access, Accessibility, Notifications and battery-optimization exemption, with each grant auto-detected on return [§5.2]
- [ ] **ONB-04**: On Xiaomi/Redmi/POCO, Oppo/Realme/OnePlus, Vivo, Samsung and Huawei the user sees brand-specific background/autostart guidance with deep links and fallbacks [§5.2, §19.2]
- [ ] **ONB-05**: User can skip permissions and see a persistent banner plus a Permissions Health screen with live status and fix links [§5.2, §6.12]
- [ ] **ONB-06**: With usage history available, onboarding shows the last 7 days and guides the user to create a first limit [§5.2]

### Design System & Experience

- [ ] **UX-01**: User can choose Light, Dark or System theme; switching animates with a ripple reveal and persists [§10.2]
- [ ] **UX-02**: Home shows the "Liquid Time" wave whose level and color reflect remaining time [§10.4]
- [ ] **UX-03**: App uses wave components (WaveRing, WaveBackground, WaveTabBar, DurationDial with haptic ticks) built on Skia + Reanimated, rendering at 60 fps on the reference emulator [§10.4, §18]
- [ ] **UX-04**: With system Reduce Motion on, idle wave motion stops and transitions become fades [§10.5]
- [ ] **UX-05**: All text meets WCAG AA contrast in both themes; controls have TalkBack labels and 48 dp targets; UI holds up at 200% font scale [§10.6]

### Internationalization

- [ ] **I18N-01**: User can switch between English and Urdu; all UI, notifications and the native block screen use the selected language [§11]
- [ ] **I18N-02**: In Urdu the whole layout mirrors to RTL with Nastaliq font rendered without clipping [§11]
- [ ] **I18N-03**: A new language can be added with one JSON file plus one registry entry, and CI fails if any key is missing versus English [§11]
- [ ] **I18N-04**: Dates, times, numbers and durations are formatted per locale via `Intl` [§11]

### Insights, Gamification & Widgets

- [ ] **INS-01**: User can view today's total screen time, pickups, top apps and per-app timeline [§6.7]
- [ ] **INS-02**: User can view week/month category breakdown, trend vs previous period, and a 7×24 hourly heatmap [§6.7]
- [ ] **INS-03**: User can open an app detail page with usage history, opens, applied limits and extensions taken [§6.7]
- [ ] **GAM-01**: User earns a streak for each day all limits are respected, with a streak freeze every 7 days [§6.8]
- [ ] **GAM-02**: Home shows an ocean world that grows with streaks, and badges unlock with a celebration animation [§6.8]
- [ ] **NOTF-01**: User gets notifications at 80% and at 5 min left (configurable), a daily summary, and can control each channel [§6.3, §6.9]
- [ ] **WID-01**: User can add a home-screen widget showing today's total and top limited apps with remaining time [§6.10]
- [ ] **SET-01**: User can export their data (JSON/CSV) and delete all local data from Settings [§6.11]

### Parental Control

- [ ] **PAR-01**: Parent can sign in with Google or email and create a family [§5.3]
- [ ] **PAR-02**: Parent can add a child and pair the child's phone via QR or 6-digit code (valid 10 min, single use) [§7.1]
- [ ] **PAR-03**: Parent can set a Parent PIN on the child device; child settings, limits and exit require it, with lockout after 5 wrong attempts [§5.4, §7.5]
- [ ] **PAR-04**: Child device shows a persistent, non-dismissible "managed by <family>" notification while in child mode [§5.4, §22]
- [ ] **PAR-05**: Parent sees each child's today/week usage, top apps, active limits and protection status [§7.2]
- [ ] **PAR-06**: Parent can create, edit, toggle and remove any limit type for a child; an online child applies it within 10 s [§7.3]
- [ ] **PAR-07**: An offline child keeps enforcing cached rules and applies pending changes on reconnect [§7.3]
- [ ] **PAR-08**: Child can request more time (15/30/60 min + note); parent approves or denies from their phone and the grant applies on the child [§7.4]
- [ ] **PAR-09**: Parent is alerted when protection is disabled, the child phone misses heartbeats for 6 h, or wrong PIN attempts occur [§7.6]
- [ ] **PAR-10**: Parent can manage multiple children, invite a co-parent, remove a device (clears rules on the child), and delete the family [§7.7]
- [ ] **PAR-11**: Firestore security rules restrict parents to their family and child devices to their own data, verified by emulator tests [§15.3]

### AI

- [ ] **AI-01**: User can get smart limit suggestions from 7–28 days of usage and apply one with a single tap [§8.3]
- [ ] **AI-02**: User can opt in to an intent check for distracting apps that asks why they're opening it before allowing, timing or suggesting a break [§8.3]
- [ ] **AI-03**: User gets a nudge on long continuous sessions, rapid switching between distracting apps, or late-night use (detected on device) [§8.3]
- [ ] **AI-04**: User can chat with an AI coach in their selected language that can propose one-tap actions [§8.3]
- [ ] **AI-05**: User (and parent, per child) receives a weekly AI report with headline, wins, watch-outs and one suggestion [§8.3]
- [ ] **AI-06**: AI calls go directly from the app to the free Groq API via a provider-agnostic client, with a per-install daily quota and rate-limit backoff; the app shows remaining quota [§8.1, revised]
- [ ] **AI-07**: App is fully usable when AI is offline or out of quota; the Groq key is never hardcoded in the binary (delivered via Firebase Remote Config, rotatable) [§8.1, §17]
- [ ] **AI-08**: User can report any AI response from the app [§8.4]

### Quality & Compatibility

- [ ] **QUAL-01**: App runs on Android 7.0 (API 24) through API 36 with version-specific behavior handled [§19.1]
- [ ] **QUAL-02**: Cold start < 2 s, battery < 2 %/day, background memory < 60 MB on a mid-range profile [§18]
- [ ] **QUAL-03**: Crash reporting (Crashlytics) is active with no PII; crash-free users ≥ 99.5 % in closed testing [§21]
- [ ] **QUAL-04**: Enforcement is verified on real OEM devices (at least Xiaomi and Samsung) via Firebase Test Lab or testers [§19.2]

### Release & Compliance

- [ ] **REL-01**: App targets API 36 (Play's current requirement) and ships as a signed AAB with Play App Signing [§24.1]
- [ ] **REL-02**: A public privacy policy and account-deletion page exist and are linked in-app; in-app account deletion works [§17, §22]
- [ ] **REL-03**: Play Console declarations are complete: Accessibility declaration + demo video, Data Safety, content rating, target audience 18+, monitoring-tool flag, reviewer notes [§22, §24.1]
- [ ] **REL-04**: Store listing (title, short/long description, icon, feature graphic, screenshots, promo video) is published in English and Urdu with researched keywords [§25]
- [ ] **REL-05**: App passes closed testing (≥15 testers for 14 days) and Play review, then rolls out in stages [§24.1]
- [ ] **REL-06**: In-App Review prompt appears after positive moments (e.g. 7-day streak) [§25.3]

## Out of Scope

| Feature | Reason |
|---------|--------|
| Strict Mode / locking limit edits / cooldowns | User decision: control, not coercion; removal must be instant |
| Device Admin / uninstall prevention | Play review risk; child mode uses PIN + tamper alerts |
| Location, messages, calls, camera, mic, keystrokes, screen content | Privacy and Play stalkerware policy |
| Hidden/stealth child mode | Prohibited by Play monitoring-app policy |
| VPN-based blocking | Unneeded permission surface |
| Ads | Conflicts with wellbeing positioning |
| xAI Grok provider | No free tier |
| Any separate backend (Cloudflare Worker, own server) | User constraint: React Native + free Firebase services only |
| Firebase Cloud Functions / Storage / any paid service | Require paid Blaze plan; user constraint: free only |
| AI coach for child mode | Parents receive reports instead (v1) |
