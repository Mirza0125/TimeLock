## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Android NDK 27.1.12297006 download stalled repeatedly via Gradle's embedded downloader**
- **Found during:** Task 2, first two `bash scripts/run-android.sh --clean` attempts
- **Issue:** AGP's built-in SDK-component downloader opened a connection to Google's CDN for the ~2GB NDK package and stalled with zero throughput after 100-185MB, twice, despite basic connectivity to `dl.google.com` working fine for small requests. This blocked the Gradle build indefinitely (`Preparing "Install NDK (Side by side) 27.1.12297006"` never progressed).
- **Fix:** Installed the exact same NDK version directly via the official `sdkmanager` CLI (`sdkmanager --sdk_root=$ANDROID_HOME "ndk;27.1.12297006"`), which completed the full download and extraction in one uninterrupted pass. Gradle then found the component already present and skipped its own download.
- **Files modified:** none (SDK-component install only, no source changes)
- **Verification:** subsequent `bash scripts/run-android.sh --clean` completed with `BUILD SUCCESSFUL` and `APP_RUNNING`
- **Committed in:** N/A (infrastructure-only fix, no file changes to commit)

**2. [Rule 1 - Bug] `adb shell am start` exit code could abort scripts under `set -e`**
- **Found during:** Task 2/3, `run-android.sh` and `e2e-skeleton.sh` both silently stopped right after printing "Warning: Activity not started, intent has been delivered to currently running top-most instance."
- **Issue:** `am start` can return a non-zero exit code for the harmless case where the intent was delivered to an already-running top-most instance (e.g. right after `expo run:android` itself already opened the app). Under `set -euo pipefail` this aborted the script before it reached the real completion check (the pidof/UI-wait loop).
- **Fix:** Added `|| true` to every `adb shell am start` call in both scripts; the subsequent pidof/UI-wait loop is the authoritative success check, not `am start`'s own exit code.
- **Files modified:** `scripts/run-android.sh`, `scripts/e2e-skeleton.sh`
- **Verification:** `bash scripts/run-android.sh --clean` and `bash scripts/e2e-skeleton.sh` both complete cleanly end to end
- **Committed in:** `f66ab0f` (run-android.sh), `44f9f98` (e2e-skeleton.sh)

**3. [Rule 1 - Bug] `--device` retry fallback used an invalid identifier**
- **Found during:** Task 2, after an interrupted first build attempt triggered the retry path
- **Issue:** The fallback retried `expo run:android --device "$ANDROID_SERIAL"` (e.g. `emulator-5554`), but Expo's `--device` flag expects an AVD/device *name*, not a raw adb serial, and rejected it with `CommandError: Could not find device with name: emulator-5554`.
- **Fix:** Changed the fallback to omit `--device` entirely, letting Expo auto-select the sole connected device.
- **Files modified:** `scripts/run-android.sh`
- **Verification:** code review + primary path (`--device Medium_Phone_API_36.1`) succeeded in the final runs, so the fallback path itself is a defense-in-depth fix, not exercised in the passing run
- **Committed in:** `f66ab0f`

**4. [Rule 1 - Bug] `emu-ui.mjs` uiautomator parser silently skipped clickable parent nodes**
- **Found during:** Task 3, `scripts/e2e-skeleton.sh` failed to find `id:strategy-homeNotification` even though `dump` showed the app rendered correctly
- **Issue:** The XML node-matching regex (`/<node\b[^>]*\/>/g`) only matched self-closing tags. React Native's `Pressable`/`Button` elements render as a parent `<node>` wrapping a child `<node>` for their label `TextView`, so the parent tag is *not* self-closing and carries no matching entry - exactly the elements the script needs to tap by testID were silently invisible to it.
- **Fix:** Changed the regex to match any `<node ...>` opening tag (`/<node\b[^>]*>/g`), whether self-closing or a parent with children.
- **Files modified:** `scripts/emu-ui.mjs`
- **Verification:** `node scripts/emu-ui.mjs wait id:definitely-not-a-real-test-id 2000` now correctly lists all resource-ids including the strategy buttons before reporting not-found; `bash scripts/e2e-skeleton.sh` now taps `strategy-homeNotification` and `strategy-activityFirst` successfully
- **Committed in:** `44f9f98`
