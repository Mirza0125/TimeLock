## Phase Goal

ROADMAP Goal (verbatim): A reproducible Expo SDK 57 project runs on the emulator with full quality tooling, the shared enforcement contract is frozen, and the API 36 block-launch question is answered with a working fallback before any enforcement code depends on it.

This plan's slice: **the block path.** When the designated test app (Clock) opens, the plugin-declared accessibility service interrupts it — through the native block Activity (confirmed) or through the `GLOBAL_ACTION_HOME` + notification fallback — driven by the strategy the user set from JS in Plan 01-01.

<objective>
Generate all native Android config for enforcement through one config plugin (FND-02), and build the two-path block cascade in the local module (FND-03). A service detects Clock and a BlockLauncher tries the block Activity. It confirms the launch with a resume signal within 800 ms and otherwise falls back to `GLOBAL_ACTION_HOME` plus a heads-up notification. The persisted `BlockStrategy` can force either path, so both paths get exercised.

Purpose: The spike (Plan 01-07) needs both paths wired as production code so it can measure them. A "fallback-only" result must already be a working, planned outcome (ARCHITECTURE Anti-Pattern 1; research Pitfall 3).
Why wave 4: this plan needs Plans 01-01 and 01-02 (module + lint gates). It is serialized after Plan 01-03 because it runs repo-wide lint/typecheck/test gates and shares node_modules, android/ and the single emulator.
Output: config plugin, app.json wiring, 4 Kotlin files, module strings, and an adb service-control script.
</objective>

```kotlin
// BlockOutcomeDecider.kt — pure Kotlin, NO android.* imports
enum class BlockPath { NONE, ACTIVITY, FALLBACK }
enum class BlockOutcomeReason(val wireName: String) { DISABLED("disabled"), CONFIRMED("confirmed"), UNCONFIRMED("unconfirmed"), LAUNCH_ERROR("launchError"), FORCED("forced") }
data class BlockDecision(val path: BlockPath, val reason: BlockOutcomeReason)
object BlockOutcomeDecider {
  const val CONFIRM_DEADLINE_MS = 800L
  const val DEBOUNCE_MS = 1500L
  fun initialPath(strategy: BlockStrategy): BlockPath            // OFF→NONE, ACTIVITY_FIRST→ACTIVITY, HOME_NOTIFICATION→FALLBACK
  fun isConfirmed(attemptAtMs: Long, resumedAtMs: Long): Boolean // resumedAtMs >= attemptAtMs && resumedAtMs - attemptAtMs <= CONFIRM_DEADLINE_MS
  fun resolveActivityAttempt(launchThrew: Boolean, confirmed: Boolean): BlockDecision // threw→FALLBACK/LAUNCH_ERROR; confirmed→ACTIVITY/CONFIRMED; else FALLBACK/UNCONFIRMED
  fun forcedFallback(): BlockDecision                             // FALLBACK/FORCED
  fun disabled(): BlockDecision                                   // NONE/DISABLED
  fun shouldAttempt(nowMs: Long, inFlightUntilMs: Long): Boolean // nowMs >= inFlightUntilMs
}
// BlockActivity.kt
object BlockSignals { @Volatile var lastResumedAtMs: Long }     // SystemClock.elapsedRealtime() at onResume, -1 initially
// const EXTRA_BLOCKED_PACKAGE = "expo.modules.screenguard.extra.BLOCKED_PACKAGE"
```

<assumption_delta_decision>
Detector: `assumption-delta scan 1` fired on `pluralization` ("…answered with a working fallback…"). The block interruption now has two variants.
- Primary noun: **block interruption**, modeled as `BlockLauncher` producing `BlockDecision(path ∈ {ACTIVITY, FALLBACK}, reason)`. `BlockActivity` is the UI of one variant. It is not what "blocked" means.
- Decision: **promote**. The fallback is a first-class path, chosen either by strategy or by an unconfirmed or failed activity launch. No code may equate "blocked" with "BlockActivity is visible".
- Invariant test (accepted, Plan 01-06 Task 2, `BlockOutcomeDeciderTest`): every non-disabled attempt resolves to exactly one path; an unconfirmed or failed activity attempt always resolves to FALLBACK; homeNotification always resolves to FALLBACK. It goes red if a later phase reintroduces the "Activity only" assumption.
