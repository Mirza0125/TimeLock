# Developer Guide

Full developer reference for ScreenLimiter: prerequisites, one-time setup, running the app,
every quality gate as a single command, the native-config rules, the shared enforcement
contract, and how to re-run the block-launch spike. See [README.md](../README.md) for the
short quick start; this document is the complete reference.

## Prerequisites

- Node 24, managed via [nvm](https://github.com/nvm-sh/nvm) (`nvm install 24 && nvm use 24`).
- JDK 17 installed at `~/.local/jdk/jdk-17` (Eclipse Temurin or equivalent).
- Android SDK at `~/Android/Sdk` with platforms 33 through 36 and build-tools 36.1 installed.
- AVD `Medium_Phone_API_36.1` created and started: `emulator -avd Medium_Phone_API_36.1`. The
  rest of this guide assumes it is already running and visible as `emulator-5554` (`adb devices`).
- No sudo is required anywhere in this workflow, and no paid or cloud build service (EAS or
  otherwise) is used — every build in this guide is local.

## One-time setup

Run these once per machine, from the repo root:

```
. scripts/env.sh
corepack enable
pnpm install --frozen-lockfile
```

`scripts/env.sh` is sourced (never executed) — it exports Node 24, `JAVA_HOME`, `ANDROID_HOME`,
`ANDROID_SERIAL` and `EXPO_ANDROID_DEVICE` into the current shell. Every script in this repo
sources it internally, but interactive commands run directly from your shell (like the `pnpm`
gate commands below) need it sourced first.

## Run the app

Non-interactive full build + install + launch, the same command a fresh clone uses:

```
bash scripts/run-android.sh --clean
```

This prebuilds (`expo prebuild --platform android`), starts Metro in the background, builds and
installs the debug APK, launches it on the emulator, and prints `APP_RUNNING pid=<pid>` when the
app is confirmed running. Drop `--clean` for a faster incremental prebuild once `android/` already
exists.

For the interactive development loop (hot reload, Metro in the foreground) use:

```
pnpm android
```

Two environment variables override device targeting, both already exported by `scripts/env.sh`
with sensible defaults:

- `EXPO_ANDROID_DEVICE` — the AVD name Expo passes to `--device` (default `Medium_Phone_API_36.1`).
- `ANDROID_SERIAL` — the adb serial every script targets (default `emulator-5554`).

## Quality gates

Each gate is a single command and passes independently, in any order, from a fresh shell after
`. scripts/env.sh`:

| Command             | Checks                                                                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm lint`         | ESLint 9 flat config (`eslint-config-expo` baseline) with `--max-warnings 0`, then self-tests the RTL no-left/right rule and prints `RTL_RULE_OK` |
| `pnpm format:check` | Prettier, check-only                                                                                                                              |
| `pnpm typecheck`    | `tsc --noEmit` across the whole project                                                                                                           |
| `pnpm test`         | Jest via the `jest-expo` preset                                                                                                                   |
| `pnpm lint:kotlin`  | ktlint (`org.jlleitschuh.gradle.ktlint`) over `modules/screen-guard/android`                                                                      |
| `pnpm test:kotlin`  | JUnit (`:screen-guard:testDebugUnitTest`)                                                                                                         |

Run all six in sequence with one command:

```
pnpm verify
```

Native config and installed-APK permissions have their own aggregate, separate from `pnpm verify`
because it requires a built `android/` project:

```
pnpm verify:native
```

`pnpm verify:native` runs `scripts/verify-native-config.sh` (proves `expo prebuild --clean` is
byte-reproducible and idempotent) followed by `scripts/audit-apk-manifest.sh` (checks the built
APK's permissions against `scripts/permission-allowlist.txt`).

## Native config rules

`android/` is generated by `expo prebuild` and is gitignored. It is **never** edited by hand —
any hand edit is silently discarded the next time `expo prebuild --clean` runs. Every native
Android change goes through one of exactly two places:

- `plugins/withScreenGuardAndroid.js` (the config plugin — manifest entries, accessibility XML,
  permissions) or `app.json`.
- `modules/screen-guard` (the native module's own Kotlin/TypeScript sources).

After any change to either, re-run `pnpm verify:native` to confirm the generated project and its
permissions are still correct. A newly declared permission needs a corresponding line in
`scripts/permission-allowlist.txt` with a reason; permissions not in that allowlist (or explicitly
denylisted there) fail the audit and are never allowed through.

## RTL style rule

Use logical style properties (`start`/`end`) instead of physical ones (`left`/`right`) in every
component and stylesheet, so the app mirrors correctly once Urdu/RTL ships (product spec §11).
The ESLint rule enforces this in `app/`, `src/`, and `modules/*/src`. If a rule hit is a genuine
false positive on a non-style object, suppress it on that single line with a comment stating the
reason — do not disable the rule file-wide.

## Shared contract

`modules/screen-guard/src/ScreenGuard.types.ts` is a frozen contract — its shapes do not change
casually. `modules/screen-guard/shared-test-vectors/rule-evaluation.json` is the single source of
truth for rule-evaluation test data, loaded by both the Jest suite (via a plain `import`) and the
JUnit suite (via a Gradle `sourceSets.test.resources.srcDir` pointing at the same file — never a
copy). Any change to the shared contract updates all three together in the same commit: the
TypeScript types, the shared vectors file, and the Kotlin mirror that consumes them — never one
without the others.

## Accessibility service for development

For headless spike and E2E verification, enable or disable the ScreenGuard accessibility service
directly via adb, without touching the Settings UI:

```
bash scripts/guard-service.sh enable
bash scripts/guard-service.sh disable
bash scripts/guard-service.sh status
```

**Caveat:** this adb-based enablement bypasses Android 13+'s Restricted Settings block on
sideloaded apps. A real user who sideloads the app and tries to enable the accessibility service
through the Settings UI hits Restricted Settings friction that this dev-loop command never
exercises — that onboarding flow is Phase 7's responsibility, not proven by anything in this
guide.

## Block-launch spike

The block-launch spike measures whether the accessibility service can start the block Activity
directly from the background (BAL) versus needing the `GLOBAL_ACTION_HOME` + notification
fallback, and records the result as a decision. Re-run it with:

```
pnpm spike:block-launch
```

or, to control the trial count directly:

```
bash scripts/spike-block-launch.sh --trials 5
```

Evidence (logcat captures, screenshots, and a machine-readable `summary.json`) lands in
`.planning/phases/01-foundation-block-launch-spike/spike-evidence/`. The recorded decision itself
is [docs/decisions/0001-block-launch-path.md](decisions/0001-block-launch-path.md) — re-run the
spike and update that ADR whenever a re-validation trigger listed in the ADR fires (a new Android
release, a `targetSdk` bump, a new manifest permission, or the project's yearly re-validation
cadence).

## Troubleshooting

- **Run `corepack enable` / `corepack use` only from the repo root.** Running it from any other
  directory writes a fresh `package.json` (and `pnpm-lock.yaml`) into that directory as a side
  effect.
- **TypeScript is pinned to `~5.9.3`.** The Expo SDK 57 template resolves `~6.0.3` by default, and
  TypeScript 7 is known to break `app.config.ts` compilation — do not let it float to `latest`.
- **ESLint is pinned to 9.** `eslint-config-expo`'s flat config and its plugin peer ranges target
  ESLint 9's flat-config format; ESLint 8 or an old `.eslintrc.js` will not pick it up correctly.
- **Jest comes via `npx expo install`, not a bare `pnpm add`.** `jest-expo` pins a specific Jest
  29.x range; installing `jest@latest` (30.x) alongside it breaks the preset. Use
  `npx expo install jest-expo jest` and let Expo's resolver choose the compatible pair.
- **`EXPO_NO_GIT_STATUS=1`** is set by the build scripts to skip `expo prebuild`'s interactive
  git-status prompt in non-interactive runs.
- **Metro / `adb reverse tcp:8081`.** `scripts/run-android.sh` runs `adb reverse tcp:8081
tcp:8081` automatically after starting Metro; if the app can't reach the bundler, re-run that
  command manually or restart Metro with `bash scripts/metro.sh stop && bash scripts/metro.sh
start`.
- **Build logs** land at `${TMPDIR:-/tmp}/screenlimiter-build.log` and
  `${TMPDIR:-/tmp}/screenlimiter-metro.log` — tail these first when a build or Metro start fails
  silently.
